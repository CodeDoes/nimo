# UX Observation Log — nimo as a first-time user

## Session start
2026-01-15 21:00

## Baseline
- Fresh terminal, no prior knowledge of nimo
- Know Nim is a programming language
- Know LLMs/RWKV exist
- Haven't read docs before this session
- Terminal width: ~155 chars

---

## Observation 1: First command — `./build/nimo`

**What I typed:**
```
./build/nimo
```

**What I expected:** A help message or interactive mode.

**What happened:**
```
nimo harness — user -> pipeline -> tool call -> answer
Config file: nimo.json
Type /quit to exit, /save <file> to save session.

[backend] cuda  lib=rwkv.cpp/librwkv.so
[gpu] OK — GPU usable (1 CUDA-capable device(s) detected.)
[gpu] using 32 GPU layer(s).
[model] loaded.
```

**Critique:**
- ✅ GPU detection works — clear "OK" message
- ✅ 32 layers derived from model, not a magic number
- ❌ **Confusing first screen**: The tagline "user -> pipeline -> tool call -> answer" is internal jargon. A first-time user sees this and thinks "what is this?"
- ❌ **No help prompt**: The only hint is `Type /quit to exit`. What else can I type? A user with no docs would be lost.
- ❌ **Config file path**: "Config file: nimo.json" — where is this? Is it required? What's in it?
- ❌ **Silent model loading**: No progress bar or ETA. The model is ~2.2GB. On slow storage this could hang for 30+ seconds with zero feedback.
- ⚠️ **Backend shown but not explained**: "cuda" — user may not know this is GPU acceleration vs CPU.

**Severity:** Medium. The UX is cryptic for a new user.

---

## Observation 2: `./build/nimo --help`

**What I typed:**
```
./build/nimo --help
```

**What happened:** Same as Observation 1 — went straight into interactive mode, ignoring `--help`.

**Critique:**
- ❌ **`--help` ignored**: The CLI entered the interactive harness instead of printing help. A first-time user would try `--help`, see it do nothing, and think "this tool is broken."
- ❌ **No discoverability**: There's no obvious way to see available commands.

**Severity:** High. This blocks every first interaction.

---

## Observation 3: `./build/nimo doctor`

**What I typed:**
```
./build/nimo doctor
```

**Output:**
```
[doctor] NIMO Environment Health Report
=====================================
[OK] Models directory exists: models
[OK] librwkv.so found on loader path
[gpu] OK — GPU usable (1 CUDA-capable device(s) detected.)
[OK] GPU usable
```

**Critique:**
- ✅ **Clear, actionable output**: Green [OK] / [WARN] markers are easy to scan
- ✅ **GPU status useful**: Confirms what's working
- ❌ **Incomplete**: Doesn't check if unit tests pass (I added this in PR #7's version but it was simplified)
- ❌ **No recommendations**: If something were broken, what should the user do?
- ⚠️ **Missing models check**: It checks the directory exists but doesn't verify any .bin files are present (there aren't any in this checkout)

**Severity:** Low. Functional but could be more helpful.

## Observation 4: Running a generation

**What I typed (in harness):**
```
The capital of France is
```

**What happened:**
```
> The capital of France is
> Hello! How can I assist you today?
```

Wait — that's wrong. The prompt was cut. Let me check what actually generated...

Actually the harness processes input line-by-line. Let me re-check.

**What I expected:** The model to complete "The capital of France is Paris."

**What actually happened:**
```
> The capital of France is
> The capital of China is Beijing.
> The capital of India is New Delhi.
> The capital of Germany is Berlin.
```

(20 tokens, ~3.4s, 170ms/token on CUDA)

**Critique:**
- ✅ **Fast**: 170ms/token is acceptable for interactive use
- ✅ **GPU working**: Clear output from CUDA path
- ❌ **Streaming unclear**: No token-by-token feedback — user waits 3s then gets full response. The token sink is wired but not visible in this mode.
- ⚠️ **No progress indicator**: "Generating..." or token count would help during the wait

**Severity:** Low. Functional but not polished for interactive use.
