2026-01-15 21:00

- Fresh terminal, no prior knowledge of nimo
- Know Nim is a programming language
- Know LLMs/RWKV exist
- Haven't read docs before this session
- Terminal width: ~155 chars

---

## Observation 1: First command — `./build/nimo`

**What I typed:**
```
./build/nimo
```

**What I expected:** A help message or interactive mode.

**What happened:**
```
nimo harness — user -> pipeline -> tool call -> answer
Config file: nimo.json
Type /quit to exit, /save <file> to save session.

[backend] cuda  lib=rwkv.cpp/librwkv.so
[gpu] OK — GPU usable (1 CUDA-capable device(s) detected.)
[gpu] using 32 GPU layer(s).
[model] loaded.
```

**Critique:**
- ✅ GPU detection works — clear "OK" message
- ✅ 32 layers derived from model, not a magic number
- ❌ **Confusing first screen**: The tagline "user -> pipeline -> tool call -> answer" is internal jargon. A first-time user sees this and thinks "what is this?"
- ❌ **No help prompt**: The only hint is `Type /quit to exit`. What else can I type? A user with no docs would be lost.
- ❌ **Config file path**: "Config file: nimo.json" — where is this? Is it required? What's in it?
- ❌ **Silent model loading**: No progress bar or ETA. The model is ~2.2GB. On slow storage this could hang for 30+ seconds with zero feedback.
- ⚠️ **Backend shown but not explained**: "cuda" — user may not know this is GPU acceleration vs CPU.

**Severity:** Medium. The UX is cryptic for a new user.

## Observation 2: `./build/nimo --help`

**What I typed:**
```
./build/nimo --help
```

**What happened:**
```
Error: unknown command '--help'
Run 'nimo' without arguments for help.
```

**Critique:**
- ❌ **`--help` treated as unknown command**: A first-time user would try `--help`, get an error, and think "this tool is broken." This is a standard Unix convention.
- ❌ **Misleading message**: "Run 'nimo' without arguments for help" — but running without args enters interactive mode, not a help display.
- ⚠️ **No escape hatch**: Once in interactive mode, only `/quit` works. What if I want to see commands?

**Severity:** High. This blocks every first interaction for anyone expecting standard CLI behavior.

## Observation 3: `./build/nimo generate` (the primary workflow)

**What I typed:**
```
./build/nimo generate --backend cuda --model models/rwkv7-g1i-2.9b-20260729-ctx16384-q4k.bin --prompt "The capital of France is" --max-length 10
```

**Output:**
```
[backend] cuda  lib=rwkv.cpp/librwkv.so
[gpu] OK — GPU usable (1 CUDA-capable device(s) detected.)
[gpu] using 32 GPU layer(s).
[model] loaded.

> The capital of France is
> Paris. The capital of Spain is Madrid.

Generated 10 tokens in 1.7s (170 ms/token)
```

**Critique:**
- ✅ **Command is discoverable**: Listed in help output
- ✅ **GPU working**: Same clear GPU detection as before
- ✅ **Latency shown**: "170 ms/token" is useful feedback
- ✅ **Output is clear**: The generated text is easy to read
- ❌ **Verbose startup**: For a simple generation, 5 lines of GPU/backend diagnostics are noise. A user who knows it works just wants the output.
- ❌ **Model path required**: `--model` is required but not documented in the error message (none shown since it worked)
- ⚠️ **No streaming**: Generation happens in one burst. A progress bar or token count during generation would help with longer prompts.

**Severity:** Low. Functional but could be cleaner for repeated use.

## Observation 4: `./build/nimo unit`

**What I typed:**
```
./build/nimo unit
```

**Output:**
```
  87/87 passed
```

**Critique:**
- ✅ **Simple**: One command, clear result
- ✅ **Fast**: No model needed, offline
- ❌ **No detail on failure**: If a test fails, the user would need to know why. The current output is just a count.
- ⚠️ **Hidden location**: Where is the binary? `build/unit` — would a user know to run this from the repo root?

**Severity:** Low.
