### Critique
- **Severity: Medium.** Two kinds of noise a human should never see:
  1. The compiler recompiles + prints ~11 warnings on every `nimble run` (this is the 
     documented workflow per MEGA_INSTRUCTIONS). Feels broken even though it works.
  2. `ggml_cuda_init` internals leak into every generate/chat/harness session.

## Fixes applied

### A. Silence ggml init chatter (src/rwkv.nim)
`ggml_cuda_init: GGML_CUDA_FORCE_*` lines are `GGML_LOG_INFO` from ggml-cuda.cu printed
to stdout during `rwkv_init_from_file`. Added `withSilentBackendInit[T]` which dups
stdout+stderr to /dev/null around the init call and restores them after. Real failures
are not lost — a failed load sets rwkv's last-error string, which the caller already
reads (`rwkv_get_last_error`).

**Verified:** `generate`, `chat`, `harness` now start with only our clean lines:
```
[backend] cuda  lib=librwkv_cuda.so
[gpu] OK — GPU usable (1 CUDA-capable device(s) detected.)
[gpu] using 32 GPU layer(s).
[model] loaded.
[model] cached state for system prompt.
```

### B. Remove compiler-flagged unused imports
- `nimo.nim`: dropped `strformat`, `sequtils`, `./harness`
- `chat.nim`: dropped `terminal`, `./tokenizer`, `cuda_backend`, `vulkan_backend`
- `generate.nim`: dropped `cuda_backend`, `vulkan_backend`
- `test_state_bake.nim`: dropped `strformat`, `random`, `./macros`
- `bootstrap.nim`: `json` looked unused but is actually needed for the offline test
  seam (`parseJson` at line 46) — kept it. (This was caught by the offline unit build;
  import cleanup was validated against `nimble unit`.)

**Result:** `nimble build` still exits 0 for all 12 binaries; the unused-import
warnings are gone from the log. Remaining warnings: `sha1` deprecation (needs
`checksums` package — not installed in devenv), `Effect` exception annotations,
`result` shadowing, and test_state_bake's `StmtListLambda` — all Low.
