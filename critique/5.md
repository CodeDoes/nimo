# Critique: Real-Human UX Simulation (tmux), Day 2

Fresh-user journey, executed one command at a time in tmux exactly as a first-time
user would type them, following the README and MEGA_INSTRUCTIONS.

---

## Step 1 — First README step: `nimble build`

### User action
`devenv shell` then `nimble build`

### Output observed
```
nico.nimble(65, 31) Error: undeclared identifier: 'args'
printPkgInfo() failed.
```
**Result: FAILED to even load nimble.** The `model_evals` task used `exec "./build/model_evals" @args` — `@args` is not a valid Nimble identifier in Nim 2.2.10, which broke the **entire `.nimble` parse** and therefore **every** `nimble` command (build, run, unit).

### Critique
- **Severity: High.** The very first documented command failed. A first-time user is blocked before anything works.
- Regression introduced by the recent `model_evals` task commit; the CPU-removal commit then exposed a second failure.

### Fixes applied
- Removed the invalid `@args` in the `model_evals` task (it now prints "run directly: build/model_evals").
- Added an explicit `task build` alias (rename of `build_allTask`) so `nimble build` is well-defined.

## Step 2 — `nimble build` (retry after @args fix)

### Output observed
```
src/generate.nim(119,3) Error: not all cases are covered; missing: {bkCpu}
...
src/main.nim(21,28) Error: type mismatch  ... nGpuLayers = -1
Build failed for the package: nico
```

### Critique
- **Severity: High.** The build was already broken by an incomplete "remove CPU backend" refactor and a stale `main.nim`.
- My earlier "remove CPU" commit removed the `of bkCpu` case branches but never removed `bkCpu` from the enum — every exhaustive `case` over `RwkvBackendKind` became a compile error. The enum/CPU module were left half-removed.

### Fixes applied (completed the GPU-only removal)
- Removed `bkCpu` from `RwkvBackendKind` in `src/config.nim` + the `"cpu"` parse branch.
- `src/rwkv.nim`: dropped `of bkCpu: cpuBackend()` and the cpu_backend import.
- `src/bootstrap.nim`: dropped the `of bkCpu:` load branch and import.
- `src/generate.nim` / `src/chat.nim`: dropped cpu_backend import; their `case` statements are now exhaustive.
- Deleted legacy modules `src/rwkv/backend/cpu/cpu_backend.nim`, `src/rwkv_cpu.nim`, `src/rwkv_cuda.nim`, `src/rwkv_vulkan.nim` (orphaned; nothing buildable imports them).
- `src/main.nim`: `nGpuLayers = -1` cannot convert to `uint32` — the legacy binding test now passes `0`.

**Result:** `nimble build` → exit 0. All 12 binaries compile.

## Step 7 — `./bin/nimo harness` — 5-turn conversation

Tested the critical multi-turn path (the exact "turn 3+ repetition loop" from critique/4).

### Output
- Startup: `[backend] cuda lib=librwkv_cuda.so` (confirms the LFS-relocated lib path works at runtime), `[gpu] using 32 GPU layer(s)`, model loaded, system-prompt state cached.
- T1 `my name is Alice...` → "Nice to meet you, Alice..."
- T2 `what is my name and what do I love?` → "Your name is Alice and you love programming."
- T3 `what is the capital of France?` → "The capital of France is Paris."
- T4 `write me a short poem about the sea` → **tool call**: `wrote poem.md` / "poem written" (3 steps)
- T5 `what is my name again?` → "Your name is Alice."

### Critique
- **Severity: None.** This is the big, positive finding: **the turn 3+ repetition loop could NOT be reproduced.** Memory persists across all 5 turns, tool-calling works, `/quit` clean.
- Prior critiques recorded the loop on an older build; the state-bake + token-0 fixes since appear to have resolved it. Worth a longer soak, but not reproducible here.
