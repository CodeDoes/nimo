# Critique: Backend Library Separation & Documentation Update

## Summary
Successfully separated rwkv.cpp backend libraries and simplified documentation to focus on CUDA/CPU only.

## Changes Made

### 1. Backend Library Structure
- Built separate libraries for each backend:
  - `librwkv_cuda.so` — CUDA + cuBLAS (111M)
  - `librwkv_cpu.so` — CPU only (1.1M)
  - `librwkv_vulkan.so` — kept but not prioritized

### 2. Nimble Task Updates
- Added `build_libs` task to build all backend libraries
- Simplified `nico.nimble` to focus on CUDA/CPU workflow

### 3. Backend Module Updates
- Updated `cpu_backend.nim`, `cuda_backend.nim`, `vulkan_backend.nim`
- Each backend now points to its dedicated library

### 4. Smoke Test Simplification
- `scripts/smoke_test.sh` now tries CUDA first, falls back to CPU
- Removed Vulkan/AMD from primary flow

### 5. Documentation Update
- `AGENTS.md` updated to reflect CUDA/CPU focus
- Removed Vulkan/AMD references from commands and descriptions

## Lessons Learned

1. **Separate libraries per backend** is cleaner than trying to build a universal library
2. **RUNPATH fixes** are critical — must remove stubs and add real driver paths
3. **Documentation focus** prevents confusion — CUDA/CPU is the right scope for this hardware

## Next Steps

- Consider removing `librwkv_vulkan.so` build from default workflow
- Add CPU fallback testing to CI if needed
