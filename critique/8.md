# Critique: Real-Human UX Simulation — Round 4 (help/discovery + PATH)

Round 4: walk the higher-level `new`/`story`/`workspace`/`planner`/`run`
commands the README advertises as the "natural-language interface", exactly as
a first-time human would discover them (i.e. by trying `--help`).

---

## Step 1 — `*. --help` discovery run

### Observed
A human's first instinct for every subcommand is `--help`. Results were mixed
and often bad:

| Command | Result | Problem |
|---------|--------|---------|
| `nimo` (bare) / `nimo --help` | ✓ full usage | — |
| `planner --help` | treated `--help` **as a goal**; printed a garbage "plan" for the goal "--help" | wrong output |
| `new --help` | treated `--help` **as a goal**, **wrote a real plan file to disk**, said "To run: nimo run …" | **side-effecting** + wrong |
| `workspace --help` | `Error: unknown workspace command '--help'` | no discoverable help |
| `story --help` | `Error: unknown story command '--help'` | no discoverable help |
| `run --help` | `Error: plan not found: --help` | wrong (path vs help) |

### Critique
- **Severity: High for `new --help`** (side-effect: a user typing `--help`
  creates garbage files), **Medium otherwise**. Every subcommand should treat
  `--help`/`-h`/`help` the same way: print its own usage and stop. Instead each
  handler guessed differently, and the goal/path-based ones consumed `--help`
  as real input.

### Fix (src/nimo.nim)
Added a uniform guard at the top of all five handlers
(`planner`, `new`, `run`, `workspace`, `story`):
```nim
if rest.len == 0 or rest[0] in ["--help", "-h", "help"]:
  echo """Usage: …"""
  return …
```
Now every `nimo <cmd> --help` prints that command's usage and performs **no
side effects**.

### Verified
```
$ nimo planner --help   → Usage: nimo planner "<goal>" …
$ nimo workspace --help  → Usage: nimo workspace <command> [args]
$ nimo story --help      → Usage: nimo story <command> [args]
$ nimo run --help        → Usage: nimo run <plan_path> [--resume]
$ nimo new --help        → Usage: nimo new "<goal>"
```
Junk plan files created during the test (`plan_20260807*.json`) removed.

## Step 2 — stale docs the first user would read

### Problems
- README Features table: `Generate (CUDA/CPU/Vulkan)` — **CPU backend was
  removed** months of fixes ago; still advertised.
- README: `Evals ✓ (34/34)` — actual suite is **103/103**.
- README/USAGE: `L2: real-model smoke (GPU/CPU)` / `~176ms/token` — GPU-only now.
- MEGA_INSTRUCTIONS: "CPU fallback only when explicitly allowed" — no CPU backend.

### Fix
Corrected all: GPU-only backend list, `103/103`, `nimo-unit` naming, and an
expanded `Using nimo without ./bin/` section (PATH export **and** symlink
option) so the #1 first-run friction ("command not found") is addressed in docs.
