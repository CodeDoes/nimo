# Critique: Real-Human UX Simulation — Round 3 (state-cache hygiene)

Round 3: test and harden the runtime state cache — the one documented
"known issue" that can silently poison a session for a human.

---

## Step 1 — Repeated harness runs / cache inspection

### Observed
- Harness starts and runs cleanly across many sessions.
- `.nimo/state-cache/` had accumulated **619 MB** of `.state.bin` files
  (21 MB each) with **no cleanup ever** — one per baked context, never pruned.

### Critique
- **Severity: Medium.** Unbounded cache growth on user disk; nobody asks for it.
- The bigger risk (PROGRESS "Known Issues"): a corrupted cache entry with the
  *correct file size* loads silently. The loader only checked size — a
  same-size garbage file becomes a poisoned baked state → garbage/NaN model
  output with no explanation. A human can't recover without
  `rm -rf .nimo/state-cache`.

## Fixes applied (src/rwkv/state/cache.nim)

### A. Corruption guard — self-heal on load
`loadStateFromFile` now rejects a loaded state if it contains **NaN or ±Inf**
(a same-size corrupted file shows up as non-finite floats). Treated as a cache
miss → `bakeContext` re-bakes from the model. Verified offline:

```
cache-guard: 5/5 passed   (clean loads; NaN/Inf/truncated/missing rejected)
```

### B. Cache pruning — bounded disk
`pruneStateCache` runs at `initStateCache`: walks the cache dir and deletes the
**oldest** state files until the cache is under a 512 MB cap. Pruned states are
harmlessly re-baked on next use.

**Verified live:** harness start trimmed 619 MB → 496 MB (24 files), startup
still clean, turn + `/quit` work.
