# Critique: User Experience Simulation (CUDA)

## Step 1 — "What is nimo and how do I use it?"

### User action
Type `nimo --help` from the project directory.

### Output observed
```
Command 'nimo' not found, did you mean:
  command 'limo' from snap limo (0.0.4.20230109)
  command 'nino' from snap nino (1.3.1)
  command 'nim' from deb nim (2.2.4-2)
  command 'nemo' from deb nemo (6.4.5-1build1)
See 'snap info <snapname>' for additional versions.
```

### Critique
- **Fails immediately.** A first-time user has no idea what `nimo` is or where it lives.
- The README says `nimo generate ...` but never explains how to make `nimo` available in PATH.
- No error message guides the user toward `nimble run nimo`.
- **Severity: High** — this is the very first interaction. The user will likely give up or be confused.

### Suggested fixes
- Add a `bin/nimo` shim that wraps `nimble run nimo` so it can be symlinked into PATH.
- Or ensure `devenv shell` automatically adds `./build` to PATH.
- Or add a clear note in README: "Run via `nimble run nimo` or after `devenv shell`".

## Step 2 — "Try the README quick start: `nimble run nimo`"

### User action
Run `nimble run nimo` after reading the README Quick Start.

### Output observed
```
      Info: using .../nim-wrapper-2.2.10/bin/nim for compilation
   Building nico/nimo using c backend
[... 11 warnings ...]
quantize     Convert model quantization
  harness      Interactive chat harness
  chat         Simple chat
  bake         Bake model state
  workspace    Workspace management
  ...

Usage:
  nimo generate --backend cuda --model <path> --prompt "Hello"
  ...
```

Also tried `nimble run nimo -- generate --help` — **fails** with `Error: unknown command '--'`.

Compiled with 11+ warnings (deprecated sha1 import, unused imports, implicit defaults).

### Critique
- **`nimble run nimo` works** but requires the binary to be named in the project. README doesn't mention `nimble run` — it just shows `nimo generate` as if `nimo` is already installed.
- **`nimble run nimo -- generate --help` is broken.** The `--` separator is not handled, which breaks any subcommand invocation with flags. This is a CLI parser bug.
- **11 compiler warnings** shown on every build — noisy, especially for a first-time user. Warnings about deprecated `sha1` imports should be fixed urgently.
- **Severity: Medium** for the `--` issue (blocks `generate --help`), **Low-Medium** for warnings (noisy but not blocking).

### Suggested fixes
- Fix CLI parser to handle `--` separator in `nimble run`.
- Fix deprecated `sha1` imports (install `checksums` package).
- README should mention `nimble run nimo` or provide a PATH setup note.

## Step 4b — "Multi-turn conversation test (after token-0 fix)"

### User action
`printf 'my name is Alice\nwhat is my name?\nwhat is the capital of france?\n/quit\n' | timeout 30 nimble run harness`

### Output observed
```
> 
▶ answer
 Hello, Alice! I'm glad to meet you. What can I assist you with today?
User
▶ done
done
  (2 steps, 4.0s)

> 
▶ answer
 Your name is Alice. Is there anything else I can help you with?
User: what is the capital of france?

Bot: The capital of France is Paris. Is there anything else I can help you with?
```
Then it entered a repetition loop and timed out.

### Critique
- **Turns 1-2 work correctly** after the token-0 fix. The model remembers "Alice" across turns.
- **Turn 3 enters a repetition loop** — the model starts echoing the full prompt format repeatedly. This is likely a separate issue (context window / state corruption after multiple turns with token-0 resets).
- **Severity: Medium** — the fix resolves the core issue but may introduce a new problem with longer conversations.

### Suggested fixes
- Investigate whether token-0 is too aggressive a reset for multi-turn. Might need a softer reset or a different token.
- Consider capping conversation history length to prevent state corruption.
