# Critique: Real-Human UX Simulation — Round 5 (flag/session discipline + the dispatcher quoting bug)

Round 5 was driven by two directives: (1) `--help` is a real POSIX convention —
conform to it, don't "guess" (`new`/`planner` had been routing `--help` into the
NL planner); (2) **never push text into a session** — an initial message must be
explicit via `-p`/`--prompt`.

---

## Step 1 — `--help` / flag discipline

### Observed
- `new --help` / `planner --help` treated `--help` **as a goal** and even wrote
  a plan file; `workspace/story --help` errored "unknown … command"; `run
  --help` erred "plan not found".
- `new -z` / `planner -z` (any unknown flag) would be silently planned as the
  goal "-z".

### Fix (src/nimo.nim)
- `isHelpFlag` helper; every subcommand now prints its own usage on
  `--help`/`-h`/`help` and **never routes a flag onward**.
- Explicit `--help` **exits 0** (POSIX); bare no-arg usage still exits 1.
- `planner`/`new` reject any other `-`-leading token as "unexpected option"
  instead of NL-planning it. Structured flags stay out of the interpreter.

### Verified
```
workspace/run/planner/new --help  → usage, exit 0
planner -z / new -z                → Error: unexpected option '-z' …
```

---

## Step 2 — "do not push into a session; require -p/--prompt"

### Investigation
Walked every command that could take a session message:

| Command | Result |
|---------|--------|
| `generate` | rejects positional args (prompt = `--prompt` only) ✓ |
| `chat` | positional = model/vocab/state only; any free text ends in a model-not-found error (safe) |
| `harness` | positional = **legacy model/vocab** — so `nimo harness "hello"` *silently misparsed "hello" as a model path and dropped the text* |

Harness one-shot already requires an explicit `-p`/`--prompt`. The real hazard
was the *legacy positional model/vocab* path silently swallowing a bare message
as a model path.

### Fix (src/harness.nim)
If a positional arg is given but is **not an existing file** (i.e. it's clearly
not a model), the harness now errors with actionable guidance instead of
dropping the text:

```
$ nimo harness "hello there"
Error: unrecognized positional 'hello'.
  To send a message into the session, use explicitly:
    nimo harness -p "<message>"   (or --prompt)
  To pick a model file:
    nimo harness --model <path> [--vocab <path>]
```

## Step 3 — the real root cause: the dispatcher shreds quoted args

While testing `--prompt "Say OK."` I found the smoke test fail via the `nimo`
dispatcher but PASS via the raw `build/harness`.

### Cause
`src/nimo.nim` re-executes each subcommand by *joining args into a string and
shell-splitting*:
```nim
var cmdLine = binary & " " & rest.join(" ")
if execCmd(cmdLine) != 0: quit(1)
```
`--prompt "Say OK."` became two args `Say` + `OK.` → the harness then rejected
the dangling positional. This also explains past "the `--` separator is broken"
notes.

### Fix (src/nimo.nim, all 5 dispatcher sites)
`joinQuoted(binary, rest)` shell-quotes every arg:
```nim
proc joinQuoted(binary: string, args: seq[string]): string =
  result = binary
  for a in args: result.add " " & quoteShell(a)
```
Uses `execCmd` still, so the interactive REPL keeps inherited stdio (streaming
unchanged).

### Verified
```
$ ./bin/nimo harness --smoke --backend cuda --prompt "Say OK." --max-tokens 8
[smoke] prompt: Say OK.   reply: 好的。   (2.4s, exit 0)

$ ./bin/nimo harness   → interactive REPL → message → answer → /quit  (streams)
```
