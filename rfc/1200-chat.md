# 1200 — Chat

The interactive chat workflow. **Status: implemented** in `src/chat.nim`.
Replies stream through `session_manager.generateTurnStream` (see
[3600-engine.md](3600-engine.md)).

## What it is

A REPL where every message is compiled into work: the model streams its answer
token by token, and (for goals) a planner compiles the message into a plan the
engine executes. **The user never waits while the model generates.**

## How it works (step by step)

1. **Load**: parse args (`--backend`, `--device`, `--lib`, positional
   model/vocab/state paths), resolve the backend, bind the library, load the
   model and tokenizer.
2. **Seed**: evaluate a tiny greeting exchange into the state so the model
   starts in the right mood. If a baked state file was given, it's loaded
   instead (see [8000-state-bake.md](8000-state-bake.md)).
3. **Loop**:
   - print `User: ` and read a line
   - `/quit` or `/exit` → goodbye, stop
   - `/reset` → reload the model + re-seed, start over
   - otherwise → `generateTurnStream(inputLine, sink)`: every sampled token is
     emitted to the sink (the terminal) **immediately** — no buffered wait.
4. Each interaction is written to the session log (`logChatInteraction`).

## Streaming contract (RFC 3600)

```
generateTurnStream(s, prompt, sink, temp, topP, maxTokens)
  for each sampled token:
      sink(decode(token))        # emit NOW, before anything else
```

`generate.nim` already does this (`stdout.write` + `flushFile` per token) — the
streaming contract is to make every entry point behave the same way.

## Sampling defaults

Temperature 0.7, top-p 0.7 (from config). The RNG is seeded per session so
conversations are reproducible-ish.

## Commands inside chat

| Command | Effect |
|---------|--------|
| `/quit`, `/exit` | leave the chat |
| `/reset` | start a fresh session |
| `/plan <goal>` | compile the goal into a plan (planner state) |
| `/resume` | continue the last checkpointed plan from step N |
