# RFC 2160 — the Unified Protocol REPL (`nimo repl`)

> **Superseded by [2111-unified-chat.md](2111-unified-chat.md).** The separate
> REPL shell is being folded into a single `chat` entry (bare input = agent
> mode, `/`-prefixed = repl mode). Keep this file for the repl grammar.

**Status:** superseded (Phase-1 implemented; being folded into `chat`, RFC 2111)
**Author:** user + implemented via critique rounds

## The claim

A chat session is a **composition of small, deterministic operations**. The same
operations, exposed as a human-readable REPL, let a user drive the system by
hand — `send`, `queue`, `steer`, `story chapter write`, `state load` … — and
rely on exactly the machinery the chat agent uses.

> **Great news**: chat-as-ORCHESTRATED-heavier, REPL-as-small-parts are the same
> **protocol**. One registry, two drivers (a model-choosing drone vs. a human
> typing). Everything the chat can do, the REPL can do; the REPL may expose more.

### The invariant
> Every operation the chat can perform ("protocol") is callable from the REPL
> and from the one-shot CLI. The REPL and the chat read the same
> workspace/session/state and run the same functions. There is no "REPL-only"
> behavior a chat can't reproduce; there is no CLI-only path that isn't also a
> REPL command. Coherence continues to live in the program, not the model.

## Interaction model

`nimo repl` starts a line-driven shell with its own prompt:

```
$ nimo repl
nimo> ws init ./my-workspace
nimo> session new main
nimo> send "A man walks into a bar and starts complaining about taxes"
…
nimo> story chapter write next --from ./chapters/ch4.md
```

Commands that are already fixed in a chat (which model, which workspace, which
session) are *explicit and inspectable* here. Model/state is a first-class
`state` the REPL pins when you `send`, so later steps resume the same bake.

## Positional messages are never implicit

Following the "no pushing" rule: a bare message is never inferred. To put text
into a session a user types an **explicit verb**: `send "…"`, `queue "…"`,
`steer "…"`. The same bare words as a positional to `nimo chat` are an error
(`chat` wants `-p/--prompt`), because the REPL is the place where small
explicitness happens.

## Phase-1 command grammar (implemented)

```
help | ?
exit | quit

# workspace — the current dir each command acts on
ws status | ws list | ws switch <path> | ws new [name]

# session (a chat message-tree JSONL pinned to the workspace)
session new [path] | session status

# planning (interpret is deterministic, offline)
planner --dry-run "<goal>"     # default: true; prints plan steps

# the active message loop — all they can from the chat
send   "<text>"    # one agent-cycle: user -> plan -> tool -> answer
queue  "<text>"    # set aside (do not run yet)
steer  "<text>"    # run as a directive/steering (same as send, framed)
interrupt          # stop an (async) generation (best-effort; nothing yet)

# story pipeline (workspace-scoped)
story chapter write new  <path> -p "<premise>" [--skip-validate]
story chapter write next <path> --from <prev-chapter>
story chapter validate <path>
story wiki edit <path> -p "<edit directive>"

# model / state
cuda status                       # GPU probe (deterministic)
state ingest -p "<text>" <file.state>   # bake a standalone state
state load <file.state>                  # pin baked state as the resume point
```

## The seam: `bootstrapSession` is the only model entry

Every model-touching REPL command (`send`, `story chapter write`, `wiki edit`,
`state ingest`) uses the **one canonical** `bootstrapSession(cfg, cwd)` to get
`(ok, session, generate, lines)` — the exact same seam as `nimo harness` and
`nimo chat`. The REPL pins one bootstrapped session; later commands reuse its
state. No second bootstrap within a session.

## What this rejects (conventions / determinism)

- No implicit prompt-inference; a bare token is data, never a session message.
- `--help` on every repl command list that command's args and exits 0.
- Offline commands (`ws`, `session`, `planner --dry`, `validate`, `cuda`) work
  with no model; the model is only pulled in when a command needs it.

## Deliverables for Phase 1

- `src/repl.nim`: tokenizer (quote-aware), command registry, `send` w/ real
  model, offline commands, `cuda/planner/validate` that need no GPU.
- `src/repl` dispatch in `nimo.nim` + a `repl` task in `nico.nimble`.
- The chat's run_pipeline will be re-routed through the same registry (RFC 2110
  follow-up) so the two surfaces provably share one code path.
