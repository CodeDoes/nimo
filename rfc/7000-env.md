Build and runtime requirements. **Status: implemented** — matches the build scripts and runtime loader paths.


## Engines

| Engine | Library | Requirements |
|--------|---------|--------------|
| CUDA | `rwkv.cpp/librwkv.so` (ggml-cuda) | NVIDIA GPU, CUDA toolkit |
| Vulkan | `rwkv.cpp/build-amd/librwkv.so` (ggml-vulkan) | Vulkan drivers (RADV) |
| CPU | `rwkv.cpp/librwkv.so` | OpenMP, SSE/AVX |

### Backend selection (RFC 7500)

Runtime selection is controlled by the dispatcher in `src/rwkv.nim` in priority order:
1. **Config file** `nimo.json` — `"backend"` / `"lib"`
2. **Env vars** — `NIMO_BACKEND` / `NIMO_LIB` (applied on top of config)
3. **Compile-time default** (`-d:rwkvDefaultBackend=cuda`)
4. **Backend modules** (`src/rwkv_cpu/cuda/vulkan.nim`) — lowest authority, only own lib path

The single controlled switch point is `selectBackend(cfg)` + `bindBackend(path)`;
one dlopen call per harness session.

#### Backend modules

`src/rwkv_cpu.nim`, `src/rwkv_cuda.nim`, `src/rwkv_vulkan.nim` each provide a
`RwkvBackend` record with `kind`, `name`, `libPath`, `defaultGpuLayers`. They
are the LOWEST authority — they only know their own runtime lib.

`src/rwkv.nim` holds the proc-pointer globals for the rwkv.cpp C API and the
dispatcher; backends are bound once via `bindBackend(libPath)` and cached in
`loadedLib` for the process lifetime.

## Memory

- **This machine**: RTX 2050 with **4 GB** VRAM. The default **Q4_K** model is
  ~2.2 GB and fully offloads; the FP16 (5.9 GB) does not (harness clamps layers).
- **RAM**: 8GB+ for model + state
- **Storage**: 10GB+ for models + vocab
