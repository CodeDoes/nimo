# 3100 — Chat Pipeline

The interactive chat loop with plan compilation. **Status: superseded design —
`src/harness.nim` and `src/chat.nim` are being migrated to
[3500-plan-format.md](3500-plan-format.md) / [3600-engine.md](3600-engine.md).**

> Today `src/chat.nim` buffers the whole reply and prints it at once, and
> `src/harness.nim` runs the improvisation tool loop. Both contradict the design
> (streaming; plan compilation). The target is below.

## Target: every message compiles into a streaming engine

```
User types input
  → interpret(input) → PLAN (data)            planner state
  → engine.run(plan, sink)                    deterministic, STREAMING
       each step streamed token-by-token
       ▶/✔ step events
  → final answer streamed
```

### Plain chat (no tools)

`src/chat.nim`:

```
User types input
  → session.generateTurnStream(input, sink)   # every token → sink NOW
  → (optionally) a plan template is compiled for the goal
```

Supports `/reset` (reload model + re-seed) and `/quit`. **No waiting** — tokens
appear as they are sampled.

### Tool via plan (replaces the improvisation loop)

`src/harness.nim` targets:

1. Interpret the user message into a plan.
2. The engine runs each step; `Generate` steps stream through a sink.
3. Pointed tools (extract/summarize/validate/write/lookup) run deterministically.
4. `Report` steps surface progress; the final answer streams.

The old "generate → parse reply for `[tool]` → feed result back → repeat ≤8×"
loop is **removed**; tool calls live in the plan, not improvised mid-reply.
