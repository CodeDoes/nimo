# 2000 — CLI

The command surface. **Status: implemented** in `src/nimo.nim` (dispatcher)
plus one binary per tool in `src/` (built into `build/`).

## How the dispatcher works (step by step)

1. `nimo` reads the first argument.
2. If there are no arguments, it prints the help text listing all commands.
3. It looks the command up and either:
   - spawns the matching binary from `build/` (`generate`, `quantize`,
     `harness`, `chat`, `bake`, `eval`), forwarding the remaining args, or
   - runs the logic directly in the CLI (`workspace`, `story`).
4. If the command is unknown, it prints an error and the help text.

## Commands (as coded)

```
nimo generate ...          one-shot text generation
nimo quantize ...          quantize a raw model
nimo harness ...           interactive agent loop (tool calling)
nimo chat ...              simple interactive chat
nimo bake ...              bake model state to a file
nimo workspace ...         workspace management (create/list/use/status/remove)
nimo story ...             story pipeline (generate/validate/critique/outline)
nimo eval                  run the offline test suite
```

## Generate

```
nimo generate [OPTIONS] --prompt "PROMPT"
```

Options:
- `--device NAME` — target device (`gpu-0`, `cpu`, `vulkan-0`)
- `--backend CPU|CUDA|VULKAN` — pick the backend (overrides config)
- `--lib PATH` — explicit `librwkv.so` (overrides `--backend`)
- `--model PATH` — model file
- `--quant FORMAT` — verify the model's quant matches (e.g. `Q4_K`)
- `--max-length N` — max output tokens (default 60)
- `--temperature F` / `--topp F` — sampling (defaults 0.7 / 0.7)

Example:
```
nimo generate --backend cuda --model models/model-q4k.bin --prompt "Hello" --max-length 10
```

Step by step: parse args → check backend/device compatibility → check the
model's quant matches `--quant` → bind the backend library → load the model →
encode the prompt → evaluate in chunks → sample tokens until stop/max →
print text + speed.

## Chat

```
nimo chat [OPTIONS] [MODEL] [VOCAB] [STATE]
```

Options: `--backend`, `--device`, `--lib` (same meaning as generate).

Step by step: load the model → seed a greeting ("User: hi / Bot: Hello!...") →
loop: read a line → `generateTurn` → print the reply. `/reset` reloads the
model; `/quit` exits. An optional baked state file is loaded to skip the
greeting evaluation.

## Quantize

```
nimo quantize <input.bin> <format> <output.bin>
```

Step by step: check the input exists → read the 24-byte GGML header → confirm
it's raw FP16/FP32 (reject already-quantized) → bind the backend → run the
quantizer → print sizes and ratio.

## Bake

```
nimo bake [MODEL] [PROMPT_OR_FILE] [OUTPUT.bin] [VOCAB]
```

Step by step: load the model → encode the prompt → run it through the model →
write the resulting state to a binary file (see [8000-state-bake.md](8000-state-bake.md)).

## Workspace

```
nimo workspace create [NAME] [--set-default]
nimo workspace list
nimo workspace use <name|path>
nimo workspace status
nimo workspace remove <name|path>
```

Step by step (create): make `~/.ws/<name>/` with `wiki/ chapters/ sessions/
.nimo/` (+ `model-cache/ state-cache/`), write a `config.toml` and `outline.md`.
`--set-default` writes the path into `.nimo-workspace` in the current
directory so later commands can find it.

## Story

```
nimo story generate <premise> [--workspace <name>] [--chapters N]
nimo story validate <chapter> [--workspace <name>]
nimo story critique <chapter> [--workspace <name>]
nimo story outline [--workspace <name>]
```

> Note: the story logic (`src/story.nim`) is fully implemented and tested by
> evals; the CLI subcommands currently print usage placeholders. Wiring them to
> a live session is the next step (see [analysis/status.md](../analysis/status.md)).

## Eval

```
nimo eval
```

Runs `build/evals` — 34 offline checks. No model or GPU required.
