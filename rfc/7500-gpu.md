# 7500 — GPU Detection & Backend Policy

How the harness determines GPU usability and decides—before loading the model—
whether to use GPU, fall back to CPU, or refuse to start. Implemented in
`src/gpu.nim`.

## Status

Implemented.

## Backend-aware policy (RFC 7500)

The dispatcher in `src/rwkv.nim` resolves the backend (CPU / CUDA / Vulkan) from
config > env > compile-time default > backend module, then the harness's GPU
policy runs per backend kind. The NVIDIA CUDA probe (`gpuProbe` in `gpu.nim`)
runs ONLY for `backend = cuda`; the CPU and Vulkan paths skip it.

## GPU policy per backend

| backend      | GPU probe | gpuLayers | GPU unusable behavior |
|--------------|-----------|-----------|-----------------------|
| `cpu`        | skip      | 0         | none (already CPU)    |
| `cuda`       | required  | cfg.gpuLayers | **refuse to start** — clean message + fix instructions |
| `vulkan`     | skip      | cfg.gpuLayers | none (Vulkan driver handles)     |

> Note: `allowCpuFallback` is mentioned in some configs/RFCs but is **not yet
> wired** — the harness always refuses to start on an unusable GPU. See
> git history.

### Rationale

Hybrid-graphics laptops (NVIDIA discrete + AMD iGPU) can have the NVIDIA GPU in
a suspended / reset-required state while the AMD iGPU + Vulkan path remain usable.
By separating the backend choice from the CUDA probe, operators can run on AMD
Vulkan without a full reboot even when the NVIDIA side is misbehaving.

## Why

A broken or suspended discrete GPU (typical on hybrid laptops after
suspend/driver reload) makes CUDA initialization fail with `no CUDA-capable
device is detected`, and rwkv.cpp can over-commit VRAM and SIGSEGV. Probing the
GPU *before* loading the model turns these crashes into clean, actionable
messages and lets the operator choose CPU instead.

## Detection — `gpuProbe()`

Probes the NVIDIA driver directly through the CUDA Driver API in
`libcuda.so.1` (dlopen'd at runtime; independent of rwkv.cpp):

- `cuInit(0)` — if it returns `CUDA_ERROR_NO_DEVICE (100)`, the driver is
  loaded but the GPU is not usable (`pstate: [GPU requires reset]`).
- `cuDeviceGetCount()` → number of usable devices.

Returns one of:

| Status       | Meaning                                        |
|--------------|------------------------------------------------|
| `gpuAvailable` | ≥1 usable CUDA device                          |
| `gpuUnusable`  | driver present but no device (needs reset)    |
| `gpuUnknown`   | no `libcuda.so.1` found (no NVIDIA driver)    |

## Fallback policy — `decideGpu`

As coded, `decideGpu` has only two outcomes (CPU fallback is not implemented):

| GPU status | Decision         |
|------------|------------------|
| Available  | `gdUseGpu`  (use configured layers) |
| Unusable   | `gdBlocked` → harness refuses to start |
| Unknown    | `gdBlocked` → harness refuses to start |

On `gdBlocked` the harness prints the diagnosis (`[GPU requires reset]`), the
fix (reboot, or reload the nvidia driver), and how to switch to a different
backend.

## VRAM-aware layer clamp — `safeGpuLayers`

`freeVramMiB()` queries free VRAM via `cuMemGetInfo`; `modelFileInfo` reads the
model header (`nLayer`, size) off disk. `safeGpuLayers` clamps `n_gpu_layers` so
model weights + 1.5 GiB headroom (activations + KV/state) fit VRAM. Without
this, rwkv.cpp SIGSEGVs on `cudaMalloc` OOM when the model is larger than the
GPU.

```text
if modelSizeMiB + 1536 <= freeVram:  use requested layers
else:  layers = (freeVram - 1536) / (modelSizeMiB / nLayer)
```
