# 9400 — Test Strategy (deterministic — the program, not the model)

**Status: implemented (L0 + L1).**

## Why just a unit suite is not enough

`unit.nim` tests the *modules* in-process with a mock seam. It never runs the
actual CLI binary, so it cannot catch bugs that live in the **wiring**: arg
parsing, bootstrap order, the one-shot/interactive loop, session persistence,
file writes, exit codes — the exact class of bug found while building L1
(`harness` silently swallowed unknown flags as a model path instead of erroring).

## Tests vs evals

Tests validate **our deterministic code** (model stubbed/scripted, exact
assertions, CI). Evals validate **the chaotic model** (real model, rubric +
rate, manual/semi — RFC 9300). The model being deterministic-but-chaotic means
tests must stub it and evals must never assert exact tokens.

## The layers

| Layer | What it exercises | Runs | Command |
|-------|-------------------|------|---------|
| **L0 unit** | In-process pure logic: parsing, plan, session tree, config, engine, rubric scorer | offline, ms | `build/unit` |
| **L1 CLI integration** | Real harness binary + scripted model: one-shot, file write, workspace, resume, smoke, error paths, pi session JSONL | offline, s | `build/harness_offline` + `scripts/cli_test.sh` |
| **L2 real-model smoke** | Model loads and replies (CUDA/CPU) | GPU, ~5s | `scripts/smoke_test.sh` |
| **L3 golden snaps** (future) | Freeze scripted-run JSONL + file outputs; diff | offline | `tests/golden/*` |

## The key seam: a scripted model in the real CLI

`bootstrapSession` (offline build) reads `--script-replies <file>` — a JSON array
of model replies — and returns them in order. The harness passes `bs.generate`
into the turn loop. This makes the full binary path deterministic and testable
without rwkv.cpp or a GPU. `scripts/cli_test.sh` runs the scenario matrix.

## Reproducibility knobs

- **`--seed N`** — fixed sampling seed pins a chaotic run to a reproducible
  initial condition. Product default is clock-seeded (creativity); seed is a
  test/CICD knob.
- **`--script-replies file`** — scripted model for offline CLI tests.

## Running

```bash
devenv shell nimo-test             # L0 + L1 (fast, offline)
devenv shell nimo-unit            # L0 only
devenv shell scripts/smoke_test.sh # L2 (real model)
```

## Rules

1. Every behavior change ships with an L0 or L1 check.
2. L1 asserts observable behavior (exit code, files, session JSONL).
3. The model stays stubbed in tests — never assert exact output.
4. Keep `-d:harnessOffline` builds green — they are the CI workhorse.
