# 9400 — Test Strategy (layered)

**Status: implemented (L0 + L1); L2 partial (smoke).**

## Why just a unit suite is not enough

`unit.nim` tests the *modules* in-process with a mock seam. It never runs the
actual CLI binary, so it cannot catch bugs that live in the **wiring**: arg
parsing, bootstrap order, the one-shot/interactive loop, session persistence,
file writes, exit codes — the exact class of bug found while building L1
(`harness` silently swallowed unknown flags as a model path instead of erroring).

The model is non-deterministic + expensive, so most of the system must be tested
with a **scripted model**, and the real model only where necessary.

## The layers

| Layer | What it exercises | Runs on | Command |
|-------|-------------------|---------|---------|
| **L0 unit** | In-process pure logic: parsing, plan, session tree, config, engine, tokenizer, sampling | offline, ms | `build/unit` |
| **L1 CLI integration** | The real harness binary + scripted model: one-shot, file write, workspace, resume, smoke, error paths, pi session JSONL | offline, seconds | `build/harness_offline` + `scripts/cli_test.sh` |
| **L2 real-model smoke** | Model loads and replies (CUDA/CPU) | GPU, ~5s | `scripts/smoke_test.sh` |
| **L3 golden snapshots** (future) | Freeze scripted-run session JSONL + file outputs; diff to catch drift | offline | `tests/golden/*` |

## The key seam: a scripted model in the real CLI

`bootstrapSession` (offline build) reads `--script-replies <file>` — a JSON array
of model replies — and returns them in order. The harness passes `bs.generate`
into the turn loop. This makes the full binary path deterministic and testable
without rwkv.cpp or a GPU:

```bash
nim c -d:harnessOffline -o:build/harness_offline src/harness.nim
build/harness_offline --script-replies tests/fixtures/haiku_replies.json \
    -s sess.jsonl -p "write a haiku about AI"
```

`scripts/cli_test.sh` runs a matrix of black-box scenarios and asserts exit
code, stdout, session JSONL contents, and written files.

## Running everything

```bash
devenv shell nimo-test            # L0 + L1 (fast, offline)
devenv shell nimo-unit            # L0 only
devenv shell scripts/smoke_test.sh # L2 (real GPU/CPU model)
```

## Rules

1. Every behavior change ships with an L0 or L1 check.
2. L1 cases assert on *observable* behavior (exit code, files, session JSONL),
   not internals.
3. The real model stays a black box; never assert exact output in L1.
4. Keep `-d:harnessOffline` builds green — they are the CI workhorse.
